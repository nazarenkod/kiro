# planning — PLAN (крок 2)

Головний агент **не обходить репозиторій сам** — він джойнить два артефакти
(спек від `tm-case-fetcher`, мапа від `repo-scout`) і вирішує. Авторитет:
`DESIGN.md` крок 2.

## Джойн: що звідки

| Рішення плану | Джерело |
|---|---|
| feature-тека / екрани / template | мапа скаута (`feature_dir`, `screens`, `template_test`) |
| **user** | підбір з `Users.*` за передумовами спека (роль, тип рахунку) |
| **card** | критерій для `findCard{}` (тип, валюта) з передумов спека |
| **навігація** | діплінк з мапи (`deeplink`) або через home screen |
| **стаби** | які `JsonFilePath` потрібні під `request/response` спека; що вже існує (`stubs_existing`) |
| **прогалини** | обʼєднання `gaps` спека (дані ТМ) і `gaps` мапи (репо) |

## Робота з gaps
Кожен елемент обʼєднаного `gaps[]` → **конкретне питання людині** на
чекпоінті:
- «у кроці 3 плейсхолдер `{сума}` — яку суму використати?»
- «екрана X немає — створюємо чи міняємо флоу?»
- «response не parseable (`parse_ok:false`) — дай коректне тіло контракту.»

Відповіді вливаються в план. Агент **не заповнює прогалини здогадками**.

## Правило чекпоінта (risk-based)
- **Авто-прохід** лише якщо: `gaps` порожній **І** всі ресурси зарезолвлені
  (feature-тека знайдена, user/card підібрані, всі стаби існують, екрани є).
- Інакше — **пауза на людину**: план + список питань.

## План — у файл
Пиши план у `target/gen-test/plan-<checkId>.md` (не лише в чат): переживає
сесію, можна дивитись diff, потрібен для **regen-friendly** воркфлоу
(рішення 13.2 — ТМ source of truth). Момент паузи і момент відповіді
маркуй у метриках (`human_seconds`).

### Regen-friendly (рішення 13.2)
ТМ — джерело правди: той самий `checkId` за тих самих вхідних даних має
давати **той самий план**. Тому фіксуй у `plan-<checkId>.md` явно:
- обраний `Users.*` і критерій `findCard{}` (щоб повторний прогін не «плавав»);
- імена стабів (`JsonFilePath`) і рішення по колізіях;
- рішення по навігації (deeplink vs home);
- відповіді людини на gaps — щоб регенерація не питала вдруге, якщо дані ТМ
  не змінились.

## Шаблон плану

```markdown
# План: check <checkId> (functional <functionalId>) — <title>

## Спек (від fetcher)
- priority / platform / validation: ...
- steps: <N кроків>
- api.parse_ok: request=<>, response=<>

## Мапа (від scout)
- feature_dir: ...
- template_test: ...
- screens/components: ...
- deeplink: ...

## Рішення
- user: Users.<...>            # + чому
- card: findCard{ ... }        # тип/валюта
- навігація: deeplink <...> | home
- стаби: [<JsonFilePath...>]   # нові / переюз (+ рішення по колізії)
- скрол: <відомо зі скаута/template | default scroll-always>

## Traceability (step/expected → покриття в тесті)
- step 1 (<expected>) → <дія/навігація>
- step 2 (<expected>) → assert <...>   ← ЦІЛЬОВИЙ (neg-control мутує його)
- step N (<expected>) → assert <...>
# кожен expected має покриття; непокритий → ФЛАГ

## Gaps → питання людині
- [ ] <gap 1> → <питання>
- [ ] <gap 2> → <питання>

## Чекпоінт: AUTO | HUMAN
```

## Колізія стабів
Файл маппінгу з такою назвою вже існує — **не** перезаписувати й **не**
перейменовувати самовільно. Ескалація людині: «переюзати наявний / створити
під новою назвою (запропонувати назву)». Рішення фіксується в плані.
(Деталі кодогену — `references/codegen.md`.)
